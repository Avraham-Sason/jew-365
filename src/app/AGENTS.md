# AGENTS.md

## Purpose

- Own Expo Router routes, layouts, navigation, and screen-level composition.

## Ownership

- [_layout.tsx](_layout.tsx) owns root providers, fonts, RTL sync, onboarding redirect guard, `reconcileChokInstall()` and notification handler initialization (and, once the first segment is `(tabs)`, `openLaunchNotificationResponse()` for the tap that launched a killed app), the Shabbat gate, and the exported `ErrorBoundary` that expo-router installs at the root. The boundary reports its error to crash reporting once (scope `render`), and the default export is wrapped in `Sentry.wrap`; see [../services/AGENTS.md](../services/AGENTS.md).
- The Shabbat gate (`useCurrentQuietBlock()` + [ShabbatScreen](../components/ShabbatScreen.tsx)) covers every route while `quietBlockAt()` holds, once onboarded — before that the location is only a default. It re-reads at the next `nextQuietBoundary()` and on every `AppState 'active'`, keeps the `Stack` mounted and hidden from accessibility so a notification tap still has a navigator, provides the block through `QuietBlockContext`, and unwinds the stack when a block starts and after any navigation inside it, so the reader's keep-awake never runs on Shabbat.
- Every screen `Modal` closes while `useQuietBlock()` holds: a native modal would sit above the in-tree Shabbat screen.
- [_layout.tsx](_layout.tsx) mounts [UpdateBanner](../components/UpdateBanner.tsx) once onboarded, between the `Stack` and the Shabbat screen, so the ready-update strip floats over every route and the update check runs on every return to the foreground.
- [index.tsx](index.tsx) owns root redirects.
- [(tabs)/AGENTS.md](<(tabs)/AGENTS.md>) owns the main tab screens.
- [onboarding/AGENTS.md](onboarding/AGENTS.md) owns onboarding flow screens.
- [day/AGENTS.md](day/AGENTS.md) owns day drilldown routes.
- [mitzvah/AGENTS.md](mitzvah/AGENTS.md) owns mitzvah detail routes.
- [siddur/AGENTS.md](siddur/AGENTS.md) owns the nusach reader route, Chok LeYisrael included, and the `/siddur` redirect to the siddur tab, which owns the catalog.
- [taharah/AGENTS.md](taharah/AGENTS.md) owns the taharat hamishpacha dashboard, log, calendar and settings routes.
- [custom-mitzvah.tsx](custom-mitzvah.tsx) owns custom mitzvah create/edit UI, top to bottom: the name; the start and end time as two [TimeField](../components/TimeField.tsx)s, where an end before the start ends the window the next day and an end equal to the start makes it a full 24 hours, and a `typography.small` line in `goldText` under the two fields says so (`custom.window.nextDay` or `custom.window.fullDay`, with the end time); the category as a read-only pill, never a choice, derived by `categoryForWindow()` in [customMitzvah.ts](../utils/customMitzvah.ts) and drawn only while the hours are valid; the active days as a [WeekdayPicker](../components/WeekdayPicker.tsx) (`activeDays`, all seven by default, at least one to save); the Shabbat and Yom Tov skip switches; reminders; and content blocks. Every setting carries a muted hint line and, right under it, an `Affects` line (screen-local, beside `Hint`: `custom.affects` over the `custom.surface.*` names joined with ` · `, `typography.small` in `goldText`, `accessibilityRole="text"`) naming the surfaces the setting changes: the hours, the active days and the Shabbat / Yom Tov skip change home, schedule, notifications and history; the category, the library; the reminders section, notifications; the rich content, the mitzvah screen, the siddur reader and notifications. A reminder card carries none. A reminder is a label input and a row of the minutes input, the word `custom.offsetMinutes` and the anchor [SegmentedControl](../components/SegmentedControl.tsx) (`flex: 1`, both anchor labels on one line at 360 dp); under the row sit the clock time it fires at (`reminderClock()`), or an `urgent` warning when the offset falls outside the hours, the anchor hint, and a full-width compact `danger` [Button](../components/Button.tsx) (`custom.deleteReminder`, as a content block's delete). Save is refused while any reminder falls outside the hours. Switching the anchor flips the offset's sign (an `end` reminder stores a negative one). The anchor is start or end only: a custom mitzvah never stores a `clock` reminder, and the detail screen's reminder editor hides that option for it. There is no rotating-text field (the user's call on 2026-10-11). A content block is text, blessing, link, or a siddur text chosen in a [BottomSheet](../components/BottomSheet.tsx) of `SheetAction`s (the mitzvah texts, then the standalone texts by group); the form holds an unchosen siddur block as a draft with `textId: null` and drops it on save, so only a complete `ContentBlock` is stored. The draft type and the pure rules (`DraftBlock`, `cleanContentBlocks()`, `siddurTextName()`) live in [customMitzvah.ts](../utils/customMitzvah.ts), where their suite pins them; the form keeps no copy. A stored siddur block whose `textId` is no longer in `SIDDUR_TEXT_IDS` (a retired text such as `tzitzit`) shows the name stored on the block, in place of a registry name (`siddurTextName()` returns `null` for it), and is dropped on the next save. Save validates in order: name, both times (any two valid times are a window, so there is no end-after-start step), a day, a reminder, a label on every reminder, every reminder inside the hours. The form is the one source of truth for a custom mitzvah's reminders: it seeds from the detail screen's `customReminders` override when one exists, keeps each reminder's `includeContentInBody` and `skipIfDone`, and clears that override on save (`resetToDefault()`), so the scheduler and the detail screen follow what the form saved. Its header is [ScreenHeader](../components/ScreenHeader.tsx) and its delete confirmation [ConfirmDialog](../components/ConfirmDialog.tsx). Each reminder and content block is a padded [Card](../components/Card.tsx); its field labels are `field` [SectionLabel](../components/SectionLabel.tsx)s (no local label component); the add actions are `secondary` Buttons with the `plus` icon, Save the primary Button and the delete of a saved mitzvah the `danger` one; back replaces to home when there is nothing to go back to.
- [hilulot.tsx](hilulot.tsx) owns the hilulot screen: the `hilulotEnabled` switch and every hilula on its next day from the Hebrew day in effect now (`upcomingHilulot()`), with its Hebrew and civil date and how far off it is. The mitzvot library row and a hilula notice open it. Its header is [ScreenHeader](../components/ScreenHeader.tsx) and the hilulot as non-pressable [ListRow](../components/ListRow.tsx)s on one `divided` [Card](../components/Card.tsx) under a [SectionLabel](../components/SectionLabel.tsx).
- [rosh-chodesh.tsx](rosh-chodesh.tsx) owns the Rosh Chodesh screen: the `roshChodeshEnabled` switch and the next six Rosh Chodesh occurrences from the Hebrew day in effect now (`upcomingRoshChodesh()`), each a non-pressable [ListRow](../components/ListRow.tsx) with the `moon` icon, the new month's name, the Hebrew and civil date (both days of a two-day Rosh Chodesh) and how far off it is, reusing the `hilulot.today` / `tomorrow` / `inDays` words. The mitzvot library row and a Rosh Chodesh notice open it. Its header is [ScreenHeader](../components/ScreenHeader.tsx), under a [SettingsSection](../components/SettingsSection.tsx) and a [SectionLabel](../components/SectionLabel.tsx). The rows sit on one `divided` [Card](../components/Card.tsx).
- [report.tsx](report.tsx) owns the weekly report screen. Its `week` param (a date key, from the report notice) is normalised to the latest week end on or before it whose block has ended, so any date works and none reaches into the future; without one it opens the latest week. The header is [ScreenHeader](../components/ScreenHeader.tsx) with the week range (`weekStartFor()` to the week end, so a Yom Tov after Shabbat makes it longer) and that Shabbat's parasha as its subtitle and two [HeaderPill](../components/ScreenHeader.tsx)s in `actions`, previous and next week; next is disabled at the latest week and previous past `RETENTION_DAYS`, where the marks have been pruned. The body is computed live from the stores by `weekSummary()` and `upcomingWeek()` ([weeklyReport.ts](../utils/weeklyReport.ts)): `report.summary` (a `Banner` into `/checkin` while that week's check-in still has unmarked items, the `checkInPending` count with `report.pendingLine.once` for one, then a `divided` [Card](../components/Card.tsx) of [ListRow](../components/ListRow.tsx)s with marked of decided, the current streak and the best day), `report.perMitzvah` (a row per mitzvah judged that week, most missed first, muted when misses outnumber marks), `report.improve` (a `warning` `Banner` into the mitzvah, only when something was missed) and `report.upcoming` (the next week's occasions, one row per day that has one). A week with nothing judged shows `report.empty` instead of the first three. It reads the week's days through `useDayModel()` and its own store selectors; the history tab's Reports pill and the report notice open it.
- [schedule.tsx](schedule.tsx) owns the schedule, a stack route opened from the More tab's schedule row (the user's call, 2026-10-11). Its header is [ScreenHeader](../components/ScreenHeader.tsx): `schedule.title`, the cursor's date and the location name as the subtitle, and a back pill that goes back, or replaces to home when there is nothing to go back to. The header's body row holds the day / week / month toggle, a [SegmentedControl](../components/SegmentedControl.tsx), over the previous / next icon-only [HeaderPill](../components/ScreenHeader.tsx)s (`backIcon` / `forwardIcon`, named `common.previous` / `common.next`) with the cursor's date, or its month in the month view, between them. Every open starts on the day view of the app day (`appDay()`: between midnight and alot it is still the evening's date), and the week card and month cell that mark today mark that day. The day view is a timeline, on one `divided` [Card](../components/Card.tsx), of the day's zmanim and enabled mitzvot whose rows open the mitzvah (a custom one in `/custom-mitzvah`), a done row carries the `check` icon, and it labels a mitzvah waiting in an open check-in as waiting, not missed; a week card (as tall as its content) or a month cell opens `/day/[date]`. The month grid is six explicit rows of seven equal cells under a weekday header row of the same seven columns, so a date always sits under its weekday; a cell's open-count badge sits in its own row above the dates, never over them, and the grid scrolls on a short screen. The month grid is built behind `InteractionManager.runAfterInteractions`, so switching to it never freezes the screen. It reads the day through [useDayModel](../hooks/useDayModel.ts), [buildDayTimeline.ts](../utils/buildDayTimeline.ts) and [checkIn.ts](../utils/checkIn.ts), never a local copy. Week cards are borderless `surface` cards with the `cardSoft` shadow, month cells borderless, and today's week card and month cell `goldLight`.
- [mitzvot.tsx](mitzvot.tsx) owns the mitzvot library, a stack route opened from the Mitzvot row in Settings and from the onboarding ready step. Its header is [ScreenHeader](../components/ScreenHeader.tsx) with a `+` [HeaderPill](../components/ScreenHeader.tsx) into `/custom-mitzvah`; it is one list with no active / available split (the user's call, 2026-10-12): every mitzvah from `useDayModel()` in registry order, customs last, never re-sorted, so a row does not jump when its switch flips; the category filter, a wrapping [ChipRow](../components/ChipRow.tsx), is its only filter, and each mitzvah is a [ListRow](../components/ListRow.tsx), muted while disabled (Chok LeYisrael while its add-on is not installed reads as disabled, carries `chokAddonCaption()` as its caption, and its switch opens `/mitzvah/chok_leyisrael` instead of turning it on), with a `Switch` as `trailing`, every row on one `divided` [Card](../components/Card.tsx). A "הילולות צדיקים" row follows the mitzvot, shown under the all and seasonal categories whatever `hilulotEnabled` says: its switch writes that flag and a tap opens `/hilulot`. A "ראש חודש" row follows it, built from the same list of notification-setting rows (`roshChodeshEnabled`, `moon` icon, a tap opens `/rosh-chodesh`) and shown by the same rule. Suite: [__tests__/mitzvot.render.test.tsx](__tests__/mitzvot.render.test.tsx). The user asked for the hilulot here on 2026-10-08 and for Rosh Chodesh on 2026-10-11, though both are notification settings and not mitzvot.
- [checkin.tsx](checkin.tsx) owns the post-block check-in: the route that lists a block's past days for marking, because they could not be marked while they happened (the reader's "סיימתי" still marks its own window date). It keeps the block it opened with on screen after the last mark, refuses marks once the check-in's deadline has passed (the alot that ends the first weekday after the block, `checkInDeadline()`, worded `checkin.deadline` as "dawn after <weekday>"), and marks from a tap anywhere on a card's body as well as from its check button, each a separate button a screen reader reaches. Leaving with everything marked finishes the check-in. The root layout opens it by itself once per block, the first time the app is open after the block ends and onboarding is done; only the screen records `CHECK_IN_PROMPTED_KEY`, so a push that never landed is retried. Its header is [ScreenHeader](../components/ScreenHeader.tsx), whose back leaves through `close()` (home when there is nothing to go back to), and each day is headed by a [SectionLabel](../components/SectionLabel.tsx). Each card carries its mitzvah's icon (`iconFor()`), the done rows sit on a `divided` [Card](../components/Card.tsx), and "סיימתי" is the shared [Button](../components/Button.tsx).

## Local Contracts

- The router root is configured in [../../app.json](../../app.json) as `extra.router.root = "./src/app"`.
- Keep route params validated before using them in services, stores, or navigation.
- Route-level user-facing copy should use [../i18n/AGENTS.md](../i18n/AGENTS.md) unless it is narrow, static, and intentionally local.
- Screens should compose services, stores, and reusable components rather than duplicating domain logic.
- A row of selectable pills is [ChipRow](../components/ChipRow.tsx), a settings card is [SettingsSection](../components/SettingsSection.tsx), a ticking clock is [useNow](../hooks/useNow.ts), and the stage line that home and the taharah dashboard show is `renderHint(stageHint(…))` from [summary.ts](../utils/taharah/summary.ts): a screen never keeps its own copy of any of them.
- A screen never keeps its own copy of the mitzvah list, the user settings or the check-in input ([useDayModel](../hooks/useDayModel.ts)), the mitzvah display name (`mitzvahName()` in [mitzvahName.ts](../utils/mitzvahName.ts)), or the remaining-time and clock formatting (`formatRemaining()`, `clockOf()` and `clockRange()` in [clock.ts](../utils/clock.ts)).
