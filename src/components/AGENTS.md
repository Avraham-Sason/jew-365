- [UpdateBanner.tsx](UpdateBanner.tsx) floats the ready-update strip over every screen (the user's call, 2026-10-10): an absolutely positioned [Banner](Banner.tsx) (`safe` tone, `home.updateReady`, on an opaque `surface` card under the top inset, z-index below the Shabbat screen) while `useUpdates().isUpdatePending` holds and no quiet block does; a tap calls `reloadIntoUpdate()`. It also owns the update check: `downloadNewUpdate()` at mount and on every `AppState 'active'`, so the check runs whatever screen the app returns to. The root layout mounts it once, after onboarding; no screen renders its own copy. Suite: [__tests__/UpdateBanner.render.test.tsx](__tests__/UpdateBanner.render.test.tsx).
- [ShabbatScreen.tsx](ShabbatScreen.tsx) renders an in-tree overlay above the navigator, never a native `Modal`, which on iOS cannot present over another one; its emblem is `IconTile candles`. Android back exits the app. The caller decides when it shows. The file also owns `QuietBlockContext` and `useQuietBlock()`.
- A component that opens an overlay uses [BottomSheet.tsx](BottomSheet.tsx) or [ConfirmDialog.tsx](ConfirmDialog.tsx), which gate on `useQuietBlock()` themselves; only those two files render a `Modal`, as [ReminderEditor.tsx](ReminderEditor.tsx) does through `BottomSheet`.
- [ScreenHeader.tsx](ScreenHeader.tsx) is the header of every stack screen, a tab uses [NavBar.tsx](NavBar.tsx). `ScreenHeader` takes `title`, `subtitle`, `onBack` (draws the back pill, its chevron the `chevronRight` icon in Hebrew and `chevronLeft` in English), `actions` (a row at the end of the pill row, which may shrink so a wrapping group folds instead of overflowing; its callers are the report screen's previous / next week `HeaderPill`s, the library's `+` pill and the taharah dashboard's calendar and settings pills), `leading` (before the title, such as an icon tile) and `children` (a body row under the title: the reader's two-row toolbar, the schedule's view toggle over its arrows, the taharah calendar's month arrows). It also exports `HeaderPill` (`label`, `onPress`, `accessibilityLabel`, `selected`, `disabled`: a pill that turns `headerAccent` while selected, and draws at opacity 0.5 with `accessibilityState.disabled` while disabled) and `HEADER_PILL_BG` / `HEADER_PILL_BG_PRESSED`, the one translucent white a header control draws on.
- [NavBar.tsx](NavBar.tsx) draws the logo, the `title` with an optional `subtitle`, and an `actions` node at the end; it has no `left` or `right` prop.
- [SegmentedControl.tsx](SegmentedControl.tsx) is the one segmented choice (`options` as `{ value, label, accessibilityLabel? }`, the last naming an option whose visible label is short, `value`, `onChange`, `tone` `surface` or `header`, `style`); each option is a `radio` whose chosen state goes out twice: `accessibilityState` (`selected` and `checked`) for native and `aria-checked` for the web, because react-native-web 0.21 maps only the `aria-*` props to the DOM and ignores `accessibilityState`. The generic `T extends string` keeps `onChange` typed to the option values.
- [ConfirmDialog.tsx](ConfirmDialog.tsx) is the one confirmation modal: `visible`, `title`, `body`, `confirmLabel`, `cancelLabel` (default `common.cancel`), `destructive` (an `urgent` confirm button), `busy` (disables both buttons), `onConfirm`, `onCancel`. A backdrop tap and Android back both cancel.
- [BottomSheet.tsx](BottomSheet.tsx) is the one action sheet and picker host: `visible`, `title`, `caption`, `onClose`, `children`, and always a Close button of its own, so a caller adds no Cancel. It lifts above the keyboard on iOS. `SheetAction` is a row inside it (`label`, `onPress`, `destructive`); `selected` draws it on `goldLight` with the selected state, and `onLayout` lets a long list scroll the selected row into view.
- [Banner.tsx](Banner.tsx) is the status strip (`text`, `tone` `warning` | `urgent` | `safe` | `accent` | `info`, optional `onPress` which makes it a button, `style`); `bannerPalette()` is exported and picks text colours apart from the border, because the status colours read under 3:1 on their own tint.
- [SectionLabel.tsx](SectionLabel.tsx) is the heading above a list (`text`, optional `count` appended in brackets, `style`).
- [ListRow.tsx](ListRow.tsx) is the icon, title and caption row (`icon`, `iconTone` `accent` | `muted`, `title`, `caption`, `trailing`, `chevron` (the one forward chevron, the `chevronLeft` icon in Hebrew and `chevronRight` in English, never a text glyph, which right-to-left text mirrors; drawn when no `trailing` is given; the siddur tab, Settings and the More tab use it), `onPress`, `onLongPress`, `disabled`, `accessibilityLabel`, `style`); without `onPress` it is not a button, and `onLongPress` passes straight through to the `Pressable`. The mitzvot library, the siddur tab, Settings, the More tab, home's next-up row and the hilulot and Rosh Chodesh screens all use it.
- [IconTile.tsx](IconTile.tsx) is the rounded tile around an icon (`name`, `tone` `accent` | `muted` | `done`, `size`, `style`) and [MitzvahIcon.tsx](MitzvahIcon.tsx) the drawing itself (`name`, `size`, `color`, `tint`, `variant`, `strokeWidth`). `ICON_NAMES` lists every drawing (`moon`, a slim waxing crescent, marks Rosh Chodesh; `night` is the full crescent, drawn on the weekly report's upcoming-days rows; `meals`, `general` and `occasions` are the siddur catalog groups' icons, each named after its `SiddurGroup`, which a test pins; `calendar`, a page with two rings and a header line, is the More tab's schedule row; `chok`, an open book with two text lines on each page, is drawn apart from `siddur` for Chok LeYisrael; `chevronLeft` and `chevronRight` are the only chevrons: the back pill and the ListRow forward chevron pick one by language), `iconFor(mitzvah.icon)` maps a registry icon string to an `IconName` and falls back to `custom`, and `ICON_VARIANT` (`outline` | `duotone`) is the one-line switch for the icon style app-wide. A screen never draws a glyph for a mitzvah.
- [DayStepper.tsx](DayStepper.tsx) steps a device calendar day by one with arrows that follow the language direction, a civil date line over the Hebrew date, and disables a step past `min` / `max`. It also exports `formatDayLine()`, the civil date line the taharah screens share.
- [ChipRow.tsx](ChipRow.tsx) draws a wrapping row of selectable pills for any `string | number` value list: `values`, the `selected` value (or `null`), `onSelect`, `renderLabel`, and a `style` for the row. The active pill is gold; settings, the taharah screens and the city picker all use it, so a pill never gets a local copy.
- [ChoiceRow.tsx](ChoiceRow.tsx) draws one full-width selectable option row (`label`, `selected`, `onPress`): gold border and, while selected, the `check` icon of [MitzvahIcon.tsx](MitzvahIcon.tsx) in `onGold` inside a 22-point gold circle (never a text glyph), plain otherwise. It is a `radio` whose chosen state goes out as `accessibilityState` (`selected`, `checked`) and as `aria-checked`, as [SegmentedControl.tsx](SegmentedControl.tsx) does, and its callers wrap each set of options in a `radiogroup` named by the set's heading. Suite: [__tests__/ChoiceRow.render.test.tsx](__tests__/ChoiceRow.render.test.tsx). The onboarding profile and nusach steps list their choices with it, so an option row never gets a local copy.

- [SettingsSection.tsx](SettingsSection.tsx) is the bordered card the settings screens and the hilulot screen group their rows in (`title`, `children`, and the optional `collapsible`, `expanded`, `onToggle`); a screen never declares its own section. Without `collapsible` it is the static card. Suite: [__tests__/SettingsSection.render.test.tsx](__tests__/SettingsSection.render.test.tsx).

Settings is its one caller, so the palette picker never gets a local copy.
- [ScrollSpeedStepper.tsx](ScrollSpeedStepper.tsx) steps the auto-scroll speed level (`level`, `onChange`) between 1 and `SIDDUR_SCROLL_SPEEDS.length` as − level +, disabling a step past either end; `tone` draws it on the reader toolbar or on a settings card, and `compact` narrows the steps to 26 points and the level to 16 so the reader's control row fits on one line at 360 dp; Settings keeps the default size. The reader toolbar and the Settings tab both use it, so the speed control never gets a local copy.
- [ChokWeekControls.tsx](ChokWeekControls.tsx) draws the Chok LeYisrael reader's week controls in the header body: a header-tone [SegmentedControl](SegmentedControl.tsx) of the slots it is given (`chok.slotShort.*` named by `chok.slot.*`, in a `radiogroup` named `chok.slotPicker`) and, when `names` holds two parashiyot, one for `first`, `second` and `both` (in a `radiogroup` named `chok.doubleWeek`) with a [BottomSheet](BottomSheet.tsx) (`chok.askTitle`, `chok.askCaption`, `chok.onlyParasha` twice, `chok.bothParashiyot`) shown while `asking`. It holds no state; the reader owns the slot, the choice and when to ask. Suite: [__tests__/ChokWeekControls.render.test.tsx](__tests__/ChokWeekControls.render.test.tsx).
- [TimeField.tsx](TimeField.tsx) is the one `HH:MM` input (`label`, `value`, `onChange`, `style`): one pressable box, drawn like a text input (`surface2` fill, border, centred left-to-right 16 px text), holding the value or the `HH:MM` placeholder in `textMuted`, a `button` named by the label with the value as its accessibility value. Pressing it dismisses the keyboard and opens a [BottomSheet](BottomSheet.tsx) titled by the label; typing moved into that sheet (the user found a text input next to a pick button confusing). The sheet holds a `custom.typeTime` caption and a text input that takes only digits and a colon (`keyboardType` `numbers-and-punctuation`, `maxLength` 5, never auto-focused), over two [WheelPicker](WheelPicker.tsx)s side by side with a `:` between them: the hour wheel (`PICKER_HOURS`, 00 to 23) on the left and the minute wheel (`PICKER_MINUTES`, 00 to 59) on the right in both languages, because a clock time reads left to right: the three children render in reversed order when the row mirrors (`I18nManager.isRTL` on native, the Hebrew document direction on web, where react-native-web has no `isRTL`), never through a `direction` style; the wheels are named by `custom.pickHour` and `custom.pickMinute`. The sheet input holds a local draft, set to `value` each time the sheet opens. `normalizeTimeInput()` runs on every keystroke into the draft: it drops everything but digits and `:`, keeps only the first colon, inserts one after the second digit when none was typed, and caps the text at five characters (`'0830'` becomes `'08:30'`); the moment the draft matches `TIME_PATTERN` it also calls `onChange`, so a partial or impossible draft changes nothing and a draft left on close is thrown away (the value keeps its last full time). A wheel centres the hour or minute of the value while it matches `TIME_PATTERN` and 00 otherwise; settling a wheel writes `HH:MM` at once, keeping the other part of the current value, or `00` when the value is not a full time, sets the draft to it, and the sheet stays open until its own Close button. The field dismisses the keyboard before it opens the sheet, so the sheet's keyboard lift never pushes the wheels off a small screen unless the user taps the sheet input. The custom-mitzvah form uses it for both hours, so a time input never gets a local copy. Suite: [__tests__/TimeField.render.test.tsx](__tests__/TimeField.render.test.tsx).
- [WheelPicker.tsx](WheelPicker.tsx) is the alarm-clock wheel, pure JS so it ships over the air (`values`, `selected`, `onChange`, `renderLabel` defaulting to `String`, `accessibilityLabel`, `style`; `WHEEL_ITEM_HEIGHT` 40 and `WHEEL_VISIBLE_ROWS` 5). It is a `ScrollView`, not a `FlatList`, because its longest list is 60 rows: `snapToInterval`, `decelerationRate="fast"`, two rows of padding at both ends so the first and last values can sit in the centre, over a `surface2` centre band with hairline borders. The selected row is `heading` text in `text`, the others `body` in `textMuted`. The value is the row at `Math.round(offsetY / WHEEL_ITEM_HEIGHT)`, clamped to the list; `onChange` fires from `onMomentumScrollEnd` and from `onScrollEndDrag` when the drag ends with zero velocity (no momentum follows), and only when the value differs from `selected`. On web it fires 120 ms after the last `onScroll` event, and CSS `scroll-snap` does the snapping, because react-native-web does not implement `snapToInterval`. A tap on a row and the `increment` / `decrement` actions (one value, never past either end) scroll there animated and call `onChange`; a `selected` that changes from outside, and the first layout, scroll without animation, while a `selected` that only follows a scroll the user made triggers no second scroll. The scroll view is the one `adjustable` element (`accessibilityValue` is the selected label) and the rows are not separately focusable. TimeField is its one caller. Suite: [__tests__/WheelPicker.render.test.tsx](__tests__/WheelPicker.render.test.tsx).
- [WeekdayPicker.tsx](WeekdayPicker.tsx) draws seven checkbox pills in one row, Sunday (0) to Saturday (6) in `WEEKDAYS` order, named by `weekday.short.<day>` (`selected`, `onToggle`, `style`); a day is a plain `number` in props and the caller narrows it to `Weekday`. A selected pill is gold with `onGold` text, the rest `surface2`; the component only reports the pressed day, so toggling and the at-least-one-day rule stay with the caller. The custom-mitzvah form uses it for the active days. Suite: [__tests__/WeekdayPicker.render.test.tsx](__tests__/WeekdayPicker.render.test.tsx).

- [BottomTabs.tsx](BottomTabs.tsx) draws the five tabs (more, history, home, siddur, settings; the siddur tab with the `siddur` `MitzvahIcon`, the More tab with a local 2×2 grid of rounded squares) in the order the layout registers them and singles out the `home` route: a 44-point disc lifted above the bar's top edge, gold when focused and `goldLight` otherwise, ringed in the bar color. Every other tab keeps the plain icon and label. Suite: [__tests__/BottomTabs.render.test.tsx](__tests__/BottomTabs.render.test.tsx).

## Local Contracts

- Use [../theme/AGENTS.md](../theme/AGENTS.md) tokens and `useTheme()` instead of hard-coded colors unless there is a narrow reason.
- Keep components reusable and prop-driven; business rules belong in [../services/AGENTS.md](../services/AGENTS.md), [../stores/AGENTS.md](../stores/AGENTS.md), [../data/AGENTS.md](../data/AGENTS.md), or [../utils/AGENTS.md](../utils/AGENTS.md).
- Preserve RTL and Hebrew-first layout behavior. Position with direction-relative `start`/`end`; never combine a `language`-driven rotation with physical `left`/`right`, which RN swaps by `I18nManager.isRTL` instead — two sources of truth that disagree on first launch.
- The same swap applies to `textAlign`: native RN flips `left`/`right` under `I18nManager.isRTL`, while react-native-web keeps them literal, so a web preview cannot catch it. Leave `textAlign` at its start default, or derive the physical edge from `I18nManager.isRTL`, as the siddur reader does. A `TextInput`'s `textAlign` is physical on Android and web, so an LTR-only field such as a URL uses the literal `'left'` with `writingDirection: 'ltr'`.
- [MitzvahCard.tsx](MitzvahCard.tsx) takes an `icon` (`IconName`, default `custom`; callers pass `iconFor(mitzvah.icon)`) drawn as an `IconTile` in the `done` tone once completed. The card is a non-pressable `View` (fill, border, shadow, opacity 0.55 once done) around two siblings: the body `Pressable`, which covers the whole card except the buttons (tile, name, status line, the completed line with the `check` icon in `safe`, and the time ribbon) and owns `onPress`, `onLongPress`, the combined `accessibilityLabel`, the `longpress` accessibility action and the 0.85 pressed opacity; and an absolutely positioned row at the card's `end` holding the open-text button (only when the caller passes `onOpenText`; the caller decides availability through `hasSiddurText()`) and the check button, or the gold done mark, which is not a touch target so a tap on it reaches the body. A button never sits inside another button: react-native-web renders every `button` role as a `<button>`, so a nested one is invalid DOM, and on native the inner buttons would be unreachable to a screen reader. The first row reserves `buttons * (30 + spacing.md)` of end padding and its `onLayout` height sets the button row's height, so the buttons stay centred on it. The body is disabled only when it has neither `onPress` nor `onLongPress`, as on the check-in screen, where the check button still works; the check button needs `onComplete` and neither `readOnly` nor `done`, and the open-text button needs `onOpenText`. Suite: [__tests__/MitzvahCard.render.test.tsx](__tests__/MitzvahCard.render.test.tsx).
- Logic worth testing must be exported and imported by the test, never re-declared inside it.
