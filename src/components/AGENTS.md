- [ReminderEditor.tsx](ReminderEditor.tsx) is the reminder add / edit sheet of the mitzvah screen, a [BottomSheet](BottomSheet.tsx) (`visible`, `initialValue`, `mitzvah`, `location`, `settings`, `allowClock`, `mitzvahName`, `onClose`, `onSave`) whose body scrolls inside 65% of the window height (`BODY_HEIGHT_SHARE`), because the clock option's inline wheels make it taller than a 640-point screen; [WheelPicker](WheelPicker.tsx) sets `nestedScrollEnabled` so its wheels still scroll inside it on Android: a [SegmentedControl](SegmentedControl.tsx) for the anchor (`reminder.anchor.start`, `.end` and, only when the caller passes `allowClock`, `.clock`), the label, then either the offset in minutes (the -5 / +5 steppers and a numeric input) or, while `clock` is chosen, a [TimeField](TimeField.tsx) labelled `reminder.time` in its place, drawn `inline` so its typing input and wheels sit in the editor's own sheet (a native `Modal` cannot present over another one on iOS, so the field never opens a second sheet here), and the skip-if-done switch. A clock reminder stores its time as `offsetMin` minutes after midnight (`timeToMinutes()`, shown back with `minutesToTime()`) and is refused without a time (`reminder.errors.timeRequired`); going from `clock` to start or end resets the offset to 0, while start and end keep theirs. Today's window plays no part: a Friday's ends at candle lighting, yet the Chok LeYisrael evening reminder at 20:30 saves because Sunday's window carries it. A mitzvah with no window ahead (`currentOrNextWindow()` is null, such as the Omer out of its season) is not judged, since nothing could fire. Without `allowClock`, which the mitzvah screen withholds from a custom mitzvah, the control offers start and end only. The three anchor labels fit one line at 360 dp in both languages (the widest, "Start of window", measures 91.6 of 96 dp in Heebo Bold 13). Suite: [__tests__/ReminderEditor.render.test.tsx](__tests__/ReminderEditor.render.test.tsx).
- [TimeField.tsx](TimeField.tsx) is the one `HH:MM` input (`label`, `value`, `onChange`, `style`, `inline`): one pressable box, drawn like a text input (`surface2` fill, border, centred left-to-right 16 px text), holding the value or the `HH:MM` placeholder in `textMuted`, a `button` named by the label with the value as its accessibility value. Pressing it dismisses the keyboard and opens a [BottomSheet](BottomSheet.tsx) titled by the label; typing moved into that sheet (the user found a text input next to a pick button confusing). The sheet holds a `custom.typeTime` caption and a text input that takes only digits and a colon (`keyboardType` `numbers-and-punctuation`, `maxLength` 5, never auto-focused), over two [WheelPicker](WheelPicker.tsx)s side by side with a `:` between them: the hour wheel (`PICKER_HOURS`, 00 to 23) on the left and the minute wheel (`PICKER_MINUTES`, 00 to 59) on the right in both languages, because a clock time reads left to right: the three children render in reversed order when the row mirrors (`I18nManager.isRTL` on native, the Hebrew document direction on web, where react-native-web has no `isRTL`), never through a `direction` style; the wheels are named by `custom.pickHour` and `custom.pickMinute`. The sheet body (caption, typing input, wheels) is one internal `TimePicker` that the sheet and the `inline` mode both render, so the typing and wheel rules live once. The typing input holds a local draft, set to `value` when the picker mounts (each time the sheet opens) and again whenever `value` changes, while a partial draft stays as long as `value` does not change. `normalizeTimeInput()` runs on every keystroke into the draft: it drops everything but digits and `:`, keeps only the first colon, inserts one after the second digit when none was typed, and caps the text at five characters (`'0830'` becomes `'08:30'`); the moment the draft matches `TIME_PATTERN` it also calls `onChange`, so a partial or impossible draft changes nothing and a draft left on close is thrown away (the value keeps its last full time). A wheel centres the hour or minute of the value while it matches `TIME_PATTERN` and 00 otherwise; settling a wheel writes `HH:MM` at once, keeping the other part of the current value, or `00` when the value is not a full time, sets the draft to it, and the sheet stays open until its own Close button. The field dismisses the keyboard before it opens the sheet, so the sheet's keyboard lift never pushes the wheels off a small screen unless the user taps the sheet input. With `inline` the field is its label over that same body, in place: no pressable box, no `BottomSheet`, no keyboard dismissal, and the sheet's Close button is the host's. A field that already lives in a sheet uses it, because a native `Modal` cannot present over another one on iOS. The custom-mitzvah form uses the sheet field for both hours and the reminder editor the inline one for a clock reminder's time, so a time input never gets a local copy. Suite: [__tests__/TimeField.render.test.tsx](__tests__/TimeField.render.test.tsx).
- [WheelPicker.tsx](WheelPicker.tsx) is the alarm-clock wheel, pure JS so it ships over the air (`values`, `selected`, `onChange`, `renderLabel` defaulting to `String`, `accessibilityLabel`, `style`; `WHEEL_ITEM_HEIGHT` 40 and `WHEEL_VISIBLE_ROWS` 5). It is a `ScrollView`, not a `FlatList`, because its longest list is 60 rows: `snapToInterval`, `decelerationRate="fast"`, two rows of padding at both ends so the first and last values can sit in the centre, over a `surface2` centre band with hairline borders. The selected row is `heading` text in `text`, the others `body` in `textMuted`. The value is the row at `Math.round(offsetY / WHEEL_ITEM_HEIGHT)`, clamped to the list; `onChange` fires from `onMomentumScrollEnd` and from `onScrollEndDrag` when the drag ends with zero velocity (no momentum follows), and only when the value differs from `selected`. On web it fires 120 ms after the last `onScroll` event, and CSS `scroll-snap` does the snapping, because react-native-web does not implement `snapToInterval`. A tap on a row and the `increment` / `decrement` actions (one value, never past either end) scroll there animated and call `onChange`; a `selected` that changes from outside, and the first layout, scroll without animation, while a `selected` that only follows a scroll the user made triggers no second scroll. The scroll view is the one `adjustable` element (`accessibilityValue` is the selected label) and the rows are not separately focusable. TimeField is its one caller. Suite: [__tests__/WheelPicker.render.test.tsx](__tests__/WheelPicker.render.test.tsx).

## Local Contracts

- Use [../theme/AGENTS.md](../theme/AGENTS.md) tokens and `useTheme()` instead of hard-coded colors unless there is a narrow reason.
- Keep components reusable and prop-driven; business rules belong in [../services/AGENTS.md](../services/AGENTS.md), [../stores/AGENTS.md](../stores/AGENTS.md), [../data/AGENTS.md](../data/AGENTS.md), or [../utils/AGENTS.md](../utils/AGENTS.md).
- Preserve RTL and Hebrew-first layout behavior. Position with direction-relative `start`/`end`; never combine a `language`-driven rotation with physical `left`/`right`, which RN swaps by `I18nManager.isRTL` instead — two sources of truth that disagree on first launch.
- The same swap applies to `textAlign`: native RN flips `left`/`right` under `I18nManager.isRTL`, while react-native-web keeps them literal, so a web preview cannot catch it. Leave `textAlign` at its start default, or derive the physical edge from `I18nManager.isRTL`, as the siddur reader does. A `TextInput`'s `textAlign` is physical on Android and web, so an LTR-only field such as a URL uses the literal `'left'` with `writingDirection: 'ltr'`.
- [MitzvahCard.tsx](MitzvahCard.tsx) takes an `icon` (`IconName`, default `custom`; callers pass `iconFor(mitzvah.icon)`) drawn as an `IconTile` in the `done` tone once completed. The card is a non-pressable `View` (fill, border, shadow, opacity 0.55 once done) around two siblings: the body `Pressable`, which covers the whole card except the buttons (tile, name, status line, the completed line with the `check` icon in `safe`, the urgent line with the `warning` icon in `urgent` beside `state.urgentSoon` while there is no status text, and the time ribbon) and owns `onPress`, `onLongPress`, the combined `accessibilityLabel`, the `longpress` accessibility action and the 0.85 pressed opacity; and an absolutely positioned row at the card's `end` holding the open-text button (only when the caller passes `onOpenText`; the caller decides availability through `hasSiddurText()`) and the check button, or the gold done mark, which is not a touch target so a tap on it reaches the body. A button never sits inside another button: react-native-web renders every `button` role as a `<button>`, so a nested one is invalid DOM, and on native the inner buttons would be unreachable to a screen reader. The first row reserves `buttons * (30 + spacing.md)` of end padding and its `onLayout` height sets the button row's height, so the buttons stay centred on it. The body is disabled only when it has neither `onPress` nor `onLongPress`, as on the check-in screen, where the check button still works; the check button needs `onComplete` and neither `readOnly` nor `done`, and the open-text button needs `onOpenText`. Suite: [__tests__/MitzvahCard.render.test.tsx](__tests__/MitzvahCard.render.test.tsx).
- Logic worth testing must be exported and imported by the test, never re-declared inside it.
